# Deploying Haq (all free)

```
Browser / phone ──> Vercel (client PWA) ──HTTPS──> Render (FastAPI + Tesseract, Docker) ──> Neon (Postgres)
                                                       ^
                                     cron-job.org pings /api/v1/health every 10 min
```

| Piece | Service | Free-tier facts that matter |
|---|---|---|
| Database | Neon Free | No card. Autosuspends when idle and wakes in about a second |
| API | Render free web service, Docker | 512 MB RAM, slow CPU. Sleeps after 15 min idle; first request then takes about a minute. OCR takes several seconds per photo |
| Client | Vercel Hobby | Static PWA, global CDN |
| Keep-warm | cron-job.org | Pings `/health`, which does not touch the database |
| Backup | Laptop + Cloudflare quick tunnel | One public HTTPS URL, no account needed |

Do the steps in order. Each needs only the previous one's output.

## 1. Database: Neon

1. Sign up at neon.tech and create a project named `haq`. Pick the AWS Singapore region
   (closest to India and to Render's Singapore region).
2. On the project dashboard, open **Connect** and copy the connection string. Either the
   pooled (`-pooler`) or the direct string works; the server adjusts for the pooled one.
   It looks like `postgresql://user:password@ep-xxx.ap-southeast-1.aws.neon.tech/neondb?sslmode=require`.
3. Keep it for step 2. No tables are needed: the server creates them on start.

## 2. API: Render

1. Sign up at render.com with GitHub and allow access to the `Haq` repo.
2. **New → Blueprint**, pick the repo. Render reads `render.yaml` and proposes the
   `haq-api` service (Docker, free plan, Singapore).
3. Fill in the values it asks for:

   | Key | Value |
   |---|---|
   | `DATABASE_URL` | The Neon string from step 1, pasted as-is |
   | `CORS_ORIGINS` | `["https://<your-vercel-app>.vercel.app"]`. Before step 3 exists, put `["http://localhost:5173"]` and update it later |
   | `SEED_OPERATOR_PASSWORD` | A password for the two demo Bank Mitra accounts. Share it only with judges |

   `JWT_SECRET` is generated by Render. `ENV=prod` makes the server refuse to start with
   unsafe settings, such as a short secret or a localhost database.
4. **Apply**. The first build takes about 10 minutes (Tesseract and Python packages). On
   start the container runs the database migrations, then seeds the demo accounts.
5. Check it:
   - `https://haq-api.onrender.com/api/v1/health` → `{"status":"ok"}`
   - `https://haq-api.onrender.com/api/v1/health/ready` → `database: true, ocr: true`
   - `https://haq-api.onrender.com/docs` → Swagger

   The service name, and so the URL, may differ. Render shows the URL on the service page.

Every push to `main` redeploys automatically.

## 3. Client: Vercel

1. Sign up at vercel.com with GitHub. **Add New → Project**, import the repo.
2. **Root Directory**: `client`. Framework Vite is picked up from `client/vercel.json`.
3. Environment variable: `VITE_API_BASE_URL` = `https://haq-api.onrender.com/api/v1`
   (your Render URL plus `/api/v1`).
4. **Deploy**. Then put the Vercel URL into Render's `CORS_ORIGINS` (step 2.3). Render
   restarts on its own after an env change.

## 4. Keep it awake during judging: cron-job.org

1. Sign up at cron-job.org. **Create cronjob**:
   - URL: `https://haq-api.onrender.com/api/v1/health`
   - Schedule: every 10 minutes
2. Turn it on the evening before judging and off afterwards. Render's free hours cover one
   service awake all month, but there is no need to spend them.

Also open the app once about 2 minutes before your slot. The first OCR after a deploy
loads Tesseract's language data.

## 5. Backup: laptop + Cloudflare tunnel

Use this if Render or the venue network misbehaves. The phone opens one HTTPS URL. The
client serves itself and forwards `/api` to the server on the laptop, so there is no CORS
and no second URL.

One-time setup (Windows, official installer):

```powershell
winget install --id Cloudflare.cloudflared
```

Tesseract is needed for real photos (`winget install UB-Mannheim.TesseractOCR`), or use
`EXTRACTOR=mock` with the bundled sample photos.

On demo day, three terminals:

```powershell
# 1. Server against the Neon database (same data as production) or STORAGE=memory
cd server
$env:DATABASE_URL = "<neon string>"; $env:EXTRACTOR = "tesseract"
uv run uvicorn app.main:app --port 8000
```

```powershell
# 2. Client built for same-origin API calls, served with the /api proxy
cd client
$env:VITE_API_BASE_URL = "/api/v1"; npm run build; npm run preview -- --port 4173
```

```powershell
# 3. Public HTTPS URL for the phone (printed as https://<random>.trycloudflare.com)
cloudflared tunnel --url http://localhost:4173
```

Open the printed URL on the phone. Rehearse this once on the venue Wi-Fi: some networks
block tunnels, and then a phone hotspot is the fallback.

## Operating notes

- **Logs**: Render → service → Logs. Lines are JSON. Every response carries an
  `X-Request-ID` header, and 500 errors return it in `error.details.request_id`: search the
  logs for that id.
- **Readiness**: `/api/v1/health/ready` returns 503 and says which part is down (database
  or OCR).
- **Rate limits** per IP per minute: 12 uploads, 30 logins, resumes and case creations.
  Over the limit returns `429 too_many_attempts` with `Retry-After`. Tune with
  `RATE_LIMIT_UPLOADS` and `RATE_LIMIT_AUTH`.
- **Schema changes** deploy themselves: the container runs `alembic upgrade head` on start.
- **Data**: Neon dashboard → Tables, or the SQL Editor (see the database notes in the README).

## Optional: Vercel preview URLs

Previews get their own URL per branch. To let them call the API, add `CORS_ORIGIN_REGEX`
in Render → Environment, e.g. `https://haq-[a-z0-9-]+-<your-vercel-team>\.vercel\.app`.
